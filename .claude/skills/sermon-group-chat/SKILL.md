# 설교 단톡방

클로드(이 세션)가 의장이다. 챗GPT·제미나이·그록·퍼플렉시티는 `roundtable/cli.js`가 부른다.
**목적은 점수가 아니라 목사님이 말로 다 설명하지 못한 의도를 찾는 것이다.** 의장은 매 라운드 각 모델의 `intentClue`(의도 단서)를 가장 귀하게 읽는다.

## 목사님 작업 방식 (지킬 것)
- 코드 설명은 하지 않는다. 되는 것, 안 되는 것, 목사님이 하실 일만 보고한다.
- 되돌릴 수 있는 일은 묻지 말고 한다. 되돌릴 수 없는 일만 확인한다.
- 결과는 코드 블록이 아닌 일반 텍스트로 드린다.

## 1. 회의 열기
목사님 말씀에서 다음을 정한다. 빠진 것이 있을 때만 한 번에 묻는다.
- **모드**: 일회성(`once`) / 토론형(`debate`) / 투표형(`vote`, "A냐 B냐"를 물으시면). 말씀이 없으면 토론형.
- **설교 성격**: `위로` `책망` `교리` `전도` `일반` 중 하나. 의장이 원고를 읽고 정한다.
- **초안**: 구글 문서 링크를 주시면 읽어 온다. 원고는 구글 문서에 그대로 두고 저장소에 올리지 않는다.
- **막힌 지점**: 목사님 말씀 그대로.
- **배역**: 성격별 기본 배정(`roundtable/roles.js`)에서 출발해, 이 설교에 맞게 의장이 바꾼다(`roleOverrides`). 위로 설교는 "정말 위로가 되나", 책망 설교는 "너무 과하지 않나"를 파고드는 자리를 꼭 둔다.

`roundtable/meetings/` 아래에 입력 JSON을 쓰고(이 폴더는 깃에 올라가지 않는다):
`node roundtable/cli.js start --input roundtable/meetings/입력.json --state roundtable/meetings/회의.json`

## 2. 라운드 진행
라운드마다 의장 자신의 발언을 JSON으로 쓴다 (`stance`, `text`, `points`, `intentClue`; 투표형은 `vote`, `reason`).
`node roundtable/cli.js round --state … --chair … --note "의장 메모"`
- 출력의 `next`가 `round`면 한 라운드 더, `finish`면 정리한다.
- 토론형: 1라운드는 각자 첫 의견. 2라운드부터 의장이 합의 여부를 판단해 멈춘다. 5라운드에서는 반드시 멈춘다.
- 응답 없는 모델은 그 자리를 비워 두고 계속한다. 보고에 그 사실을 적는다.

## 2-1. 목사님이 중간에 끼어드실 때
회의 도중 목사님이 채팅에 의견을 주시면(예: "그록 말이 맞아, 결론이 뻔해") 다음 라운드를 돌리기 전에 그대로 넣는다.
`node roundtable/cli.js say --state … --text "목사님 말씀 원문"`
- 말씀은 다듬지 말고 원문 그대로 넣는다. 다음 라운드에 네 모델 모두에게 "목사님께서 방금 말씀하셨다"로 전달되고, 모두 거기에 직접 반응한다.
- 토론형은 합의로 멈출 참이었어도, 목사님이 말씀하시면 그 말씀에 답하는 라운드를 한 번 더 연다(5라운드 한도 안에서).
- 단톡방 화면에는 목사님 말씀이 메신저의 "내 말"처럼 오른쪽에 뜬다. 노션 기록에도 「목사님 말씀」으로 남는다.
- 목사님의 개입은 의도에 대한 가장 확실한 단서다. 보고서의 `intentClues`에 반드시 반영한다.

## 3. 실시간 보기
목사님이 "실시간으로 볼래"라고 하시면 1라운드가 끝날 때마다
`node roundtable/cli.js board --state …`로 보드를 만들고, 같은 파일 경로로 Artifact를 다시 올린다(같은 링크가 갱신된다). 첫 게시 때 링크를 드린다.
"보고만"이면 보드 없이 끝까지 최고 속도로 돌린다.

## 4. 보고
보고 JSON을 쓰고 `node roundtable/cli.js finish --state … --report …`. 형식이 빠지면 닫히지 않는다.
- `summary`: 정확히 세 줄. 바쁘시면 이것만 보신다.
- `feedback`: 각 지적에 딱지 하나 — 합당 / 수용 가치 있음 / 놓친 부분 / 논리 모순이라 중요 / 과해서 무시 가능.
- `conclusion`과 가능하면 `revision`(수정안).
- 토론형: `agreement.all`(전원 합의), `agreement.some`(일부 합의), `agreement.dissent`(끝까지 반대한 모델과 이유).
- 투표형: 다수 의견과 함께 `minority`(혼자 반대한 의견)를 반드시.
- `intentClues`: 목사님 의도에 가장 가까워 보이는 단서. 의장이 왜 그렇게 보는지 한 줄 덧붙인다.

채팅 보고 순서: 세 줄 요약 → 걸러낸 피드백 → 종합 결론과 수정안 → 노션·보드 링크.

## 5. 기록
`회의.notion.json`의 속성과 본문으로 노션 「설교 단톡방」 DB에 한 행을 만든다.
- 데이터소스 `collection://ee6a58fa-8172-46d8-99c3-d21ef4f36009` (📂 설교 아래)
- 각 모델 원문은 본문 맨 아래 접은 블록으로 남는다 (의장의 해석이 중요한 것을 걸러내지 않도록).
- 보드를 올렸으면 `보드 링크`, 원고 링크가 있으면 `원고 문서`를 채운다. 목사님이 나중에 반응을 주시면 `목사님 반응`에 원문 그대로 적는다.

## 실제 모델 연결 상태
지금은 가짜 모델만 연결돼 있다(5단계 전). 실제 회의를 하려면 아래가 필요하다.
- 클라우드 환경 변수: `OPENAI_API_KEY`, `GEMINI_API_KEY`, `XAI_API_KEY`, `PERPLEXITY_API_KEY`
- 네트워크 허용 도메인: `api.openai.com`, `generativelanguage.googleapis.com`, `api.x.ai`, `api.perplexity.ai`
키가 없을 때 목사님이 회의를 부르시면, 가짜 모델로만 돌 수 있다고 먼저 말씀드린다. 키를 채팅에 붙여 달라고 하지 않는다.
